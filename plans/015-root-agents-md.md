## Why this matters

This repo's shape is unusual and easy to violate: seven of the eight `shards/*` directories are **separate git repositories** (submodules) with their own remotes, while `shards/progress` is a plain directory tracked by the root; `shard.override.yml` files are machine-managed with a marker comment; releases must go leaves-first in dependency layers; and validation must run from the root harness, not ad hoc inside a shard. None of that is discoverable from inside, say, `shards/prompt/` — an agent (or new contributor) editing there has no signal that committing means committing to a different repo. A previous AGENTS.md was deleted; the knowledge exists in `README.md` and `docs/release-validation.md` and needs distilling into the file agents actually read.

### Step 1: Write AGENTS.md (~40-60 lines)

Structure (keep it terse — this is a guardrail file, not documentation):

```markdown
# AGENTS.md — crystal-term monorepo

## Layout: this is 8 shards, 7 of them separate git repos
- shards/{color,cursor,screen,terminfo,reader,spinner,prompt} are git
  submodules with their own crystal-term/<name> remotes. Committing inside
  them commits to THAT repo. The root repo only tracks the pointer.
- shards/progress is a plain directory tracked by the root repo (no public
  repo yet).
- lib/ directories anywhere are vendored dependency installs. Never edit.

## Verify your changes
- From the root: scripts/validate-shards.sh --local   (all shards)
- One shard:     scripts/validate-shards.sh --local --shards reader --skip-examples
- Direct:        cd shards/<name> && shards install && crystal spec --no-color
- Format:        cd shards/<name> && crystal tool format src spec

## Overrides (shard.override.yml)
- --local mode generates them with the marker
  "generated by scripts/validate-shards.sh --local". Never hand-edit;
  remove with scripts/validate-shards.sh --clean-local-overrides.

## Dependency & release order
- Order: color, cursor, screen, terminfo, reader, spinner, prompt, progress
- Releases go in layers: leaves (color/cursor/screen/terminfo) →
  middle (reader/spinner) → top (prompt/progress). See
  docs/release-validation.md.

## Test frameworks
- stdlib spec: color, terminfo, spinner, prompt, progress
- Spectator (~> 0.12): cursor, screen, reader — match the file's existing style.

## Plans
- plans/ contains executable improvement plans with their own index and
  status tracking (plans/README.md).
```
