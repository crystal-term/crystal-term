## Why this matters

Seven of eight shards declare the Spectator test framework as a dev dependency, but only three actually use it. The four phantom declarations clone an entire framework from GitLab on every `shards install` (slowing the sequential validation harness) and misrepresent the test stack. Among the real users, pins are inconsistent and lockfiles have drifted to **three different resolved versions** — screen is locked to 0.11.7, a line from 2023, so its one Spectator spec exercises a materially older framework than reader's 0.12.4. (Upstream is alive — v0.12.4 released 2026-03 — so this is hygiene, not an abandonment migration.)

## Steps

### Step 1: Remove the four phantom declarations

Edit terminfo/spinner/prompt/progress `shard.yml`; for prompt, keep the `development_dependencies:` block only if other entries exist (check — prompt's block contains only spectator). Run `shards install` in each.

**Verify**: in each of the four: `rg -n "spectator" shard.yml shard.lock` → 0 matches, and `crystal spec --no-color` → all pass (they use stdlib spec, nothing changes).

### Step 2: Pin the three real users to `~> 0.12.4`

Edit cursor/screen/reader `shard.yml` to:

```yaml
development_dependencies:
  spectator:
    gitlab: arctic-fox/spectator
    version: ~> 0.12.4
```

Run `shards update spectator` (or delete `shard.lock` + `shards install`) in each.

**Verify**: each `shard.lock` shows spectator `0.12.4` (or newer 0.12.x); `crystal spec --no-color` in cursor and reader → all pass.

### Step 3: Screen's 0.11 → 0.12 bump

Run screen's suite. Spectator 0.11 → 0.12 had DSL changes; if `spec/unit/width_height_spec.cr` or `spec_helper.cr` fails, apply the mechanical DSL updates (consult failures; typical changes are matcher/stub API renames).

**Verify**: `cd shards/screen && crystal spec --no-color` → all pass.

### Step 4: Full harness

**Verify**: `scripts/validate-shards.sh --local --skip-examples` → exit 0.
